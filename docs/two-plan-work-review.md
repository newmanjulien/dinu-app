## Earlier mistakes already discovered and corrected during the first plan

The [implementation review](local-first-review.md) documented four issues after the original 29-phase closeout: late company-exit cleanup could retire a replacement workspace (R1), Home retained-page writes confused SDK array changes with new server observations (R4), candidate construction was duplicated (R3), and malformed disposable cache registry metadata had no recovery path (R5). R1/R3/R4/R5 were then changed in source and passed the existing automated checkpoint. They remain mistakes in the original work; the native/browser interleavings are still unverified.

The first plan's final checkpoint initially failed on two outdated fixtures. The second plan's full component run initially had 28 failures from outdated route and CSM fixtures, then passed after fixture maintenance. These are evidence of late integration of large phase batches, even though the corrected commands passed and no new test cases were added.

## Paths reviewed without another confirmed finding

- The Phase 2 bar-claim hint stores only confirmed successful claims for the current member/contract pair; unknown pairs still call the server. A `false` claim can mean either another visit already claimed the pair or a link exists, so treating every `false` as a durable local claim would need a separate invalidation rule. The recent-activity panel adopts an in-flight reopen request, fences responses by scope, and renews its freshness timestamp on each delivered response. These paths have the verification limits in P4.
- The Phase 3 combined setup-booking query preserves the caller's attempt ownership and the exact-attempt rebind. A second combined query after binding is intentional and disclosed in the plan; its backend read/latency effect is still unmeasured under P6.
- The saved-document Copy link control receives `useReadQuery.currentData`, which only supplies a settled result for the current arguments, retry revision, and transport generation. The controller skips the explicit `buyerLinks.latest` preflight only for that result and still checks save state and readiness before `ensureLatest`; standalone Home card controls have no such observation and still query. The strict accessor branch remains unverified in P4.
- The Phase 2 HubSpot cache bounds exact-term pages by installation, renews the timestamp on each accepted result, and keeps deal-link eligibility in a separate live authorized read. The neighboring picker issue is A1. Neither this cache nor the recent-activity cache has C8's unchanged-result timestamp gap.
- Workspace-read storage can adopt a native open that completes after its 250 ms caller deadline if its registry lease was acquired. If the lease is still pending at the deadline, it closes the retained owner; this is the narrower parallel risk covered with C5. A fast lease rejection has a separate retry defect in C6. Template source/view callers have the separate one-shot gap in C7.
- The Phase 22 draft-journal exit callback captures the original user owner; retirement marks that owner inactive before removing it from the map, so a late callback cannot discard a replacement owner's drafts. Failed physical sessionStorage removal and full-reload recovery limits are already stated in that phase's record. The workspace store's hold/reset path blocks disk reads until a successful clear, which is the required conservative behavior while company deletion is unresolved; no additional round trip was found there.
- Visible-card warming still has a useful foreground guard: one in-flight snapshot fetch per ID, a bounded number of background downloads, and a 250 ms pause after interactions. The gap in C11 begins after a failed flight is removed; the document-resource failure set does not remove that ID from the separate snapshot download list.
- The discussion pager's normal successful older-page path replaces the unbounded reply-tail follow with a 20-row page and user-triggered Show older replies. The failure handling of that same paging path is A2/A3; the two plans' recorded phase work does not establish when those pager edits were made.
- Template authoring deliberately starts a current live detail subscription for a selected item even when its provisional IndexedDB detail is present. A4 affects how much fast provisional content survives the cache budget; it is not evidence that fixing the eviction rule would remove that live subscription.
