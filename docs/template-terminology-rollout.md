# Retired template terminology rollout

**The former executable rollout instructions are retired.** The strict application uses `templateSources`, `templateSourceChunks`, `templateSourceCertificates` and `templateSourceValidationChunks`; pointers/captures use `templateSourceId`. The temporary terminology schema, detector/maintenance gate, converter, schema generator and runner are removed. Historical work records describe their original stage only and must not be executed against current source.

The original full instructions and exact old source remain preserved outside the application tree in the [release kit's baseline](backend-preservation-cutover.md#concrete-local-release-kit). They are evidence/recovery inputs for a separately reviewed affected target, not current deployment commands. There is no current `baselineUploads` callback route; canonical `templateUploads.expirePending` retains pending/deleting source cleanup.

**NOT DEPLOYABLE TO AN UNVERIFIED POPULATED TARGET.** All live G01–G25 remain UNVERIFIED. G14/G15 require exact old expiry/sweep job IDs/arguments and old upload owners to be closed/mapped with no recreating scheduler. G16–G18 require a target mid-transition to finish under its exact preserved old maintenance/conversion bundle first, verify all six old data/mapping/progress tables empty and canonical references/accounting complete, then prove no queued/running transition or client remains. The final runtime never detects or resumes a temporary terminology schema.

Use the [preservation-first cutover](backend-preservation-cutover.md) and its concrete outside-repository runbook/converter for a verified populated current-schema target. Older/unknown schemas stop for a bounded preservation/disposition plan. Preserve original source bytes/fingerprints, file IDs, frozen captures and ordinary history; never recapture a contract from the live template. A destructive reset needs separate explicit authorization. After any conversion, recovery needs matching code/client, database, files, components and scheduler/external-outcome reconciliation, or durable forward completion; source-only revert is insufficient.

The editor remains `/template` with `/admin` redirecting there; uploads use `/templates/upload`. Active canonical authoring repair, source certification and recount remain available. Their [current procedure](template-authoring-storage.md#repair-recertification-and-release-sequence) does not include legacy full-head or terminology conversion.
